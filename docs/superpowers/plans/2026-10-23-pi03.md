# PI03 Implementation Plan

> Execution: implement inline under the user's explicit PI03 authorization; preserve unrelated files and create a PR without merge.

**Goal:** Deliver KER-63's fixed development baseline experiment with protected durable execution and reproducible comparisons.
**Architecture:** Reuse the durable job state machine through typed forecast/research adapters. Extend the existing CPU launcher with one application-owned baseline workload; keep fitting out of coordinators and keep final labels inaccessible.
**Tech Stack:** Existing Python 3.12, standard-library numerical routines, systemd CPU isolation, SQLite durable jobs and PI01 ledger. No new dependencies.
**Spec:** `docs/architecture/PI03_BASELINE_SPEC_v1.json` and `docs/architecture/PI03_PREFIT_CONTRACT.md`.

## Global constraints

Frozen predecessor hashes; development only; common UTC cutoffs; strict maturity and interval purge; embargo at least 2,419,200 seconds; five predeclared algorithms and eight total attempted slots including failures; 2,000 bootstrap draws, seed 42; original floors and 2% margin; final holdout sealed; no PI04 or merge.

## Review focus

Malformed or mismatched input/spec/source hashes fail before labels are read. Missing controls fail before fit. Cross-asset pair drift and boundary-touching labels fail closed. Cancelled/stale attempts cannot accept results after recovery. Null evidence and insufficient dependence-adjusted blocks retain the baseline.
