# PI05 bounded analytical scans implementation plan

**Goal:** qualify removal of repeated full-object scans from bounded replay preparation, compare the existing PyArrow path against a pinned isolated DuckDB candidate, and publish a PR without merge.

**Architecture:** keep the existing no-thread, no-network, read-only Linux decoder and immutable Arrow/Parquet contracts. Add a closed full-snapshot primitive scan capped at 10,000 rows; retain the 128-row inspection API. The isolated harness measures one verified scan against independent page launches. The final registered memory gate retains the original paginated production replay route. A separate application-owned qualification harness compares unchanged pages, the additive scan and DuckDB without exposing an engine/SQL selector in product services.

**Tech stack:** Python 3.12.14, locked PyArrow 25.0.1, qualification-only DuckDB 2.0.0, existing bubblewrap/seccomp/rlimits, Debian cgroup v2 accounting.

**Spec:** KER-65 and KER-90–KER-96; `docs/research/PI05_RESEARCH_FOUNDATION_2026-10-26.md`; frozen protocol `docs/validation/pi05/protocol-v1.json`. Operator execution/PR authorization: 2026-10-26. No merge.

## Constraints and rulings

- Preserve prior user changes and preparation documents; stage only reviewed PI05 paths. Work in branch ker-65-pi05 from current origin/main.
- No final-period data, fitting, calibration, new feature/revision policy, financial authority or PI03 trial consumption. Synthetic hourly development fixtures only.
- No profile relaxation to accommodate a candidate: inability to start/query/spill under the existing restrictions disqualifies it. Polars is omitted unless a workload remains unanswered after this comparison.
- Exact identities, order, schemas, ns, Decimal strings, exclusions and common pairs; no approximate tolerance for this scan. Keep validation of rows outside any selected page.
- Qualification is bounded to admitted 10,000-row replay scope; no million-row/production-capacity/Rust claims.
- Ruling: implement in the current checkout on a new branch, preserving unrelated dirty paths; no worktree copy or unrelated cleanup is needed.
- Ruling: choose the protocol's conservative fixed synthetic sizes, 7 measured process runs after one warm-up, and 25% minimum full-job reduction before measurements; these are task decisions, not literature-derived constants.

## Review focus

- Empty snapshots and >128-row snapshots must validate once and preserve every row.
- Native/IPC failure and cancellation must not expose partial scan results or leave descendants.
- Corruption outside a requested page must remain fatal; no trust cache may outlive one immutable request.
- New scan operation must use the research-ledger guard and independent primitive response validation.
- Benchmark identity must include fixture/protocol/source/lock and consume complete results with the same downstream masks.
